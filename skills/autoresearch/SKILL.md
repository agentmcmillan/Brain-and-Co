# Autoresearch: Autonomous Experimentation Loop

Run autonomous experiments inspired by [Karpathy's autoresearch](https://github.com/karpathy/autoresearch). An agent modifies code, runs the experiment, evaluates results, keeps or discards the change, and repeats.

## What It Does

- Reads a `program.md` that defines the experiment scope, evaluation metric, and constraints
- Launches an autonomous loop: modify code -> run experiment -> evaluate -> keep/discard -> repeat
- Tracks all iterations with results in a structured log
- Can run locally via the Task tool or submit to Symphony for long-running execution
- Captures discoveries to REM when complete

## Usage

```
/autoresearch program.md            # Run experiments defined in program.md
/autoresearch --create              # Scaffold a new program.md template
/autoresearch program.md --iterations 20 --budget 10
```

Or as agent:
```
use autoresearch agent
```

## Arguments

| Flag | Default | Description |
|------|---------|-------------|
| `--iterations N` | 10 | Number of experiment iterations to run |
| `--budget M` | 5 | Time budget per iteration in minutes |
| `--symphony` | off | Submit as a Symphony task for long-running execution |
| `--create` | — | Scaffold a new `program.md` template in the current directory |
| `--log <path>` | `./autoresearch-log/` | Directory for experiment logs and results |

## The program.md File

The `program.md` is the human's interface to the experiment loop. It defines what to experiment with, how to evaluate, and what constraints apply. The agent reads this file at the start of each iteration.

### Template (generated by `--create`)

```markdown
# Experiment Program

## Objective
What are we trying to improve? (e.g., reduce validation loss, increase throughput)

## Target File
Which file should the agent modify? (e.g., `train.py`, `model.py`)

## Evaluation Command
The command to run after each modification:
\`\`\`bash
python train.py
\`\`\`

## Success Metric
How to determine if a change is an improvement:
- **Metric**: (e.g., val_loss, accuracy, latency_ms)
- **Direction**: lower is better / higher is better
- **Source**: (e.g., last line of stdout, `results.json`)

## Constraints
- Time budget per run: 5 minutes
- Do not modify: (list files or patterns that are off-limits)
- Stay within: (architectural boundaries, e.g., "keep the model under 10M params")

## Context
Additional context for the agent:
- Architecture notes
- Prior results
- Known dead ends
```

## Experiment Loop

Each iteration follows this cycle:

```
1. Read program.md for objectives and constraints
2. Review current best result and experiment history
3. Propose a modification to the target file
4. Apply the modification
5. Run the evaluation command (with time budget)
6. Parse the success metric from output
7. Compare against current best:
   - Better  -> keep the change, update best result
   - Worse   -> revert the change
   - Error   -> revert, log the failure
8. Write iteration log entry
9. Repeat until iterations exhausted
```

### Iteration Log Format

Each iteration is recorded in `autoresearch-log/`:

```
autoresearch-log/
├── summary.md          # Running best result and overview
├── iteration-001.md    # What changed, result, kept/discarded
├── iteration-002.md
└── ...
```

## Symphony Integration

For long-running experiments (many iterations, large time budgets), submit to Symphony:

```
/autoresearch program.md --symphony --iterations 100 --budget 10
```

This creates a Symphony task with:
- **title**: `autoresearch: <objective from program.md>`
- **prompt**: The full program.md content plus loop instructions
- **repo_url**: Current repository
- **heartbeat**: Enabled for resumption on failure

The Symphony task runs autonomously. Monitor progress:
```bash
curl http://${CONTAINER_HOST_IP}:9100/tasks/<task-id>
```

## Local Execution (Without Symphony)

When running locally, the skill uses the Task tool to spawn a general-purpose agent that executes the loop. The agent runs in the background so you can continue working.

```
/autoresearch program.md --iterations 10
```

The spawned agent:
1. Reads `program.md`
2. Executes the loop described above
3. Writes results to `autoresearch-log/`
4. Sends a notification when complete

## Example

```
/autoresearch program.md --iterations 15 --budget 3

=== Autoresearch ===

Loading program.md...
  Objective: Minimize validation bits-per-byte
  Target: train.py
  Metric: val_bpb (lower is better)
  Budget: 3 min/iteration, 15 iterations

Starting autonomous loop...

Iteration 1/15:
  Change: Increased hidden_dim from 256 to 384
  Result: val_bpb = 1.089
  Verdict: KEPT (new baseline)

Iteration 2/15:
  Change: Switched from GELU to SwiGLU activation
  Result: val_bpb = 1.074
  Verdict: KEPT (improved by 0.015)

Iteration 3/15:
  Change: Added rotary positional embeddings
  Result: val_bpb = 1.081
  Verdict: DISCARDED (regression of 0.007)

...

=== Complete ===
Best result: val_bpb = 1.031 (iteration 12)
Total improvements: 7/15 kept
Log: autoresearch-log/summary.md
```

## Discovery Capture

After the loop completes, discoveries are written to:
- `rem/discoveries/autoresearch-<timestamp>.md` -- key findings
- `autoresearch-log/summary.md` -- full experiment summary

If Memento MCP is available, top findings are persisted:
```
remember(topic="autoresearch", type="fact",
  content="<objective>: best result <metric>=<value> after <N> iterations",
  importance=0.8, scope="permanent")
```

- Any task where you can define: modify -> run -> measure -> compare
